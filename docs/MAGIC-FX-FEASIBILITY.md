# 魔法大战：哪些能只靠特效实现

> 面向《黄金碑文》/ EP3 魔法大战的演出可行性判断。所有数字都取自本工程**现有**代码，
> 不是估计：`client/fx/PixelfxRenderer.java`、`particle/ModParticles.java`、
> `boss/BossTelegraph.java`、`client/gui/*`。

## 一句话判据

**「在天上 / 地上显现的东西」→ 特效能做；「要占体积、能被绕着看、能真正改变地形」→ 不是特效的活。**

## 现有四个特效基元与硬约束

| 基元 | 怎么用 | 硬约束（代码里的真实数值） |
|---|---|---|
| **pixelfx 序列帧** | `S2CPixelfxPacket` 一个包播一整段；`ground`（贴地）或 `billboard`（朝向相机）锚点，可缩放/转 yaw | `MAX_EFFECTS = 64`、`MAX_RENDER_DISTANCE = 128`；**2D 面片，无厚度、不遮挡、无阴影**；样例图集 1984×1104（45 帧 @20fps） |
| **自定义粒子** | `golden_butterfly`（含发光层）、`burst_star/ring/dot/butterfly` | 粒子包是「一包带 `count`」，**带宽不是瓶颈**；瓶颈在客户端：每颗都是独立对象、每帧更新，`registerSpecial` 还要切贴图，几百颗就开始掉帧 |
| **地面预警圈** | `BossTelegraph.circle` | 只做「告诉你哪里会中」，不是演出主体 |
| **HUD 层** | actionbar / title / 自绘 overlay（`RedTruthOverlay`） | 不受方块、雾、光照、深度影响；反过来也读不出世界 |

## 逐条判断

| 演出 | 纯特效能不能做 | 做法 | 主要风险 |
|---|---|---|---|
| **红字**（EP2 规则层权能） | ✅ 已实现 | HUD 层 8 方向描边 + 血字 + 淡入淡出，`/galboss redtruth` 可验 | 只影响观感，不参与判定（本来就该如此） |
| **尸体化金蝶** | ✅ 已有 | `GoldenButterflyBurst.burstAtChest` | — |
| **魔法阵** | ✅ 已有 | `tohka_convocation_circle`（ground 锚点）+ `spellCircleFx` 粒子环 | ground 面片贴着地形，斜坡上会穿 |
| **空间转移** | ✅ 可行 | `teleportTo` + 黑雾/蝴蝶 burst + 声音 | 纯表现，判定仍在服务端 |
| **万千雷枪** | ✅ 可行 | 8 根 billboard 枪影 + 8 个 ground 冲击，一次 17 实例 | 不要真的发「万千」粒子：一包能带 count，但客户端逐颗更新会掉帧 |
| **奥丁之枪 / 雷神之锤 / 雅典娜神盾**（「再现」） | ✅ 可行 | 天空 billboard 巨像 + 落点 ground 冲击 + 震屏音效；伤害走服务端 | 只能「显形后砸下」，做不出可被击落的投掷物 |
| **霜雪巨人** | 🟡 一半 | 雪雾 + billboard 巨人剪影 + 冰霜粒子 | 真 3D 巨人 = GeckoLib 实体 + 建模，成本跳到美术档 |
| **巴比伦塔坠落** | 🟡 一半 | 天空巨影 + ground 冲击 + 碎块粒子 | 「塔真的砸下来」需要结构方块或大模型实体 |
| **神兵战塔（可进入的建筑）** | ❌ 不是特效 | 只能做远景剪影；真实体量用 NBT 结构或方块搭建 | 玩家走近会穿帮：必须 ≥30 格、离玩家 ≥25 格 |
| **炼狱七姐妹** | ❌ 不是特效 | 7 套实体 + 模型 + 动画 | 纯美术工作量，别塞给特效 |
| **全屏后处理**（镜头畸变 / 色差 / 天空替换） | ❌ 不建议 | 1.20.1 要 PostChain + shader JSON | 与光影包冲突、跨版本易碎；用天幕 billboard + 雾色替代 |

## 落地顺序建议

1. **红字**（已完成）—— 最便宜、最像原著、不影响战斗数值。
2. **兵器再现**（Gungnir / Mjolnir / Aegis）—— 只要 3 张 billboard 图集 + 3 个落点冲击，
   就能把「神话兵器」这条线立起来；伤害沿用现有的服务端结算。
3. **万千雷枪**—— 用第 2 步的枪影复用同一张图集，靠「旋转 + 错峰下落」做阵列，几乎是白送。

## 预算

- 一次「万千雷枪」：17 个 pixelfx 实例（上限 64），每实例 1 包。
- 同等观感的粒子写法：一包能带 60 颗，带宽没问题；但客户端要为 480 颗粒子逐帧更新、
  反复切贴图 —— 掉的是帧时间，不是带宽。
- 图集显存：2048² 未压缩 RGBA ≈ 16.7MB／张；4 张常驻 ≈ 67MB，客户端可接受，别再翻倍。
- **结论：大尺度演出一律走 pixelfx（一包一段、每帧只画一个四边形），粒子只用于贴身细节。**
